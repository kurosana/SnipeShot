## ねらいうちモード（`FilterEngine.shouldDuel` / `countResults`）

### 判定ルール

- **ねらいうちモード発動**: `lines === 2`（`shouldDuel`）
- **系統数 `lines`**: `classifyHits` による
  - **単独系統**: ヒット集合内で `e` が1要素のポケモンが持つ系統IDの集合（`singleton.size`）
  - **残り分岐**: ヒット内に単独系統の葉が1つもない複数所属ポケモン（`remaining`）を、共有系統で連結成分に分割した数
  - `lines = singleton.size + multiComponents`
- **吸収**: 分岐前ポケモン（例: カラカラ）が、ヒット内の単独系統葉（例: ガラガラ）と同じ行にまとまる。系統数には単独系統として数えない

### 過去に引っかかった点

| 問題 | 原因 | 修正後の期待 |
|------|------|--------------|
| 進化系統数が18など異常に少ない | `e`+技セットでグループ化していた | 全件で `lines=604`（mode_all.json） |
| カラカラのみでねらいうちモードになる | 分岐前を複数系統として数えていた | `lines=1`, `duel=false` |
| カラカラ+両ガラガラでねらいうちモードにならない | 吸収ロジック未実装 | `lines=2`, `duel=true` |
| 両ガラガラのみでねらいうちモードにならない | 同上 | `lines=2`, `duel=true` |
| タマタマのみで2系統になる | 分岐フォルムを別系統扱い | `lines=1` |
| イーブイのみで8系統になる | 全進化先系統を重複カウント | `lines=1`（イーブイ単体ヒット時） |

## ドボン（`checkDobon` in `js/app.js`）

### 判定ルール

`refreshResults` 内で、次をすべて満たすとき `appendDobon()`:

1. `prevCount` / `prevLines` が null でない（初回絞り込み後）
2. `hasActiveConditions()` — 除外されていない完成済み条件が1つ以上
3. `conditionsChanged` — 条件シグネチャが前回と異なる
4. `lines === 0 || lines === 1`（ねらいうちモード未満に留まっている）
5. `count >= prevCount` **または** `prevCount !== count || prevLines !== lines`（匹数が減らない、または何らかの統計変化）

**ドボンを出さない場合**

- 初回の条件適用（`prevResultStats` 未設定）
- 条件が変わっていない再計算
- `lines >= 2`（ねらいうちモード系統に到達）
- 有効な条件が0件
- `refreshResults({ skipDobon: true })` — カンニング ON 時

### 過去に引っかかった点

| 問題 | 原因 | 修正後の期待 |
|------|------|--------------|
| 初回絞り込みでドボンが出ない | 旧ロジックが `count >= prevCount && lines <= 1` のみ | 条件変更かつ `lines` 0〜1 なら、匹数が減ってもドボン可 |
| 条件変更なしでドボンが出る | `conditionSignature` 未使用 | 条件変更時のみ |
| カンニングでドボンが出る | skipDobon 未対応 | カンニング時は出ない |
| 除外してもドボンが残る | clearDobonStack 未呼び出し | 除外ボタンでスタック消去 |
| ×削除してもドボンが残る | clearDobonStack 未呼び出し | ×ボタンでもスタック消去 |
| 複数回ドボンで画像が増殖 | append スタック | 単一表示+アニメーション再トリガー |
